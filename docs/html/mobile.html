Обзор и решения

Telegram Mini App и бот остаются отдельным каналом. Mobile app — для пользователей без Telegram, при блокировке TG, и для push + иконки на экране.

Go API + PostgreSQL
    ├── Mini App (apps/app)    ← initData, @telegram-apps/*
    ├── Telegram Bot                ← bot API, OTP, уведомления
    ├── Admin (apps/admin)        ← JWT staff
    └── Mobile (apps/mobile)    ← NEW Capacitor, mobile JWT
РешениеВыбор
Фреймворк клиентаCapacitor React + Vite + native shell
API prefix/api/mobile/v1/clinics/{slug}/...
Auth пользователяТелефон → OTP в Telegram → JWT
РепозиторийМонорепо apps/mobile/
Backend уже почти готов: все нужные данные отдаются публичными GET. Нужен новый route group без TelegramInitData и слой mobile auth.

Почему Capacitor

  • Встраивается в существующий монорепо (npm workspaces, Turborepo)
  • React + Vite — тот же стек, что apps/app и apps/admin
  • Native plugins: push, geolocation, deep links, camera
  • Ionic UI не обязателен — свой дизайн под клинику
  • Активная документация и community (capacitorjs.com)

Что переиспользуем из текущего проекта

  • @you-vet/types — DTO врачей, статей, clinic-info
  • Паттерны экранов и React Query из apps/app
  • Design tokens (tokens.css)
  • Go handlers/repositories — без дублирования бизнес-логики

Что не переносим

  • @telegram-apps/sdk-react, telegram-ui
  • TelegramOnlyScreen, initData interceptor
  • BackButton Telegram — нативная навигация / свой header

Авторизация: телефон + код в Telegram

Два независимых слоя:

СлойЗадачаРешение
Защита APIanti-scrapingrate limit, optional app key
Пользовательзапись, «мои заявки», pushJWT после OTP

Контент (статьи, врачи, расписание) на первом этапе — без логина.

Flow

Mobile App                    Backend                      Bot
   │ POST /auth/request         │                              │
   │ { phone }                  │ lookup chat_id by phone      │
   ├───────────────────────────►├─────────────────────────────►│ SendMessage(code)
   │ POST /auth/verify          │                              │
   │ { phone, code }            │ → JWT access + refresh       │
   ├───────────────────────────►│                              │

Onboarding (обязательно)

Bot API не отправляет сообщения по номеру телефона, пока пользователь не нажал /start:

  1. Открыть @VPract_bot → /start
  2. «Поделиться контактом» → backend: phone ↔ telegram_chat_id
  3. Mobile app: ввод телефона → код в TG
Блокировка Telegram: OTP через бота не работает без TG. Для сценария «app на случай блокировки» нужен SMS fallback (фаза M4). На старте — только TG OTP, если аудитория уже в боте.

Roadmap приложения

Оценка для 1 разработчика. Mini App и бот не блокируются.

M0 — Backend mobile API 1–2 нед

  • Миграции: mobile_users, auth_codes
  • GET /api/mobile/v1/clinics/{slug}/... — те же handlers
  • POST auth/request, verify, refresh
  • Bot: handler contact → phone ↔ chat_id
  • Rate limit на mobile routes

M1 — Capacitor shell, read-only 3–4 нед

  • apps/mobile: Vite + React + Capacitor
  • Экраны: главная, статьи, врачи, расписание, груминг
  • Свой UI, @you-vet/types, empty/error states
  • Internal: Android debug APK, iOS TestFlight

M2 — Auth + запись + push 2–3 нед

  • Login: телефон → код в TG
  • Deeplink onboarding в бота
  • PRD-03: заявки на приём (общий backend)
  • @capacitor/push-notifications

M3 — Store release 2–4 нед

  • Privacy policy, иконка, скриншоты
  • RuStore → Google Play → App Store
  • CI: mobile-build.yml

M4 — Polish

  • SMS OTP fallback
  • «Мои заявки», offline cache статей
  • App attestation
ScopeСрок
M0 + M1 (read-only app)~1.5–2 мес
M2 (auth + запись + push)+1–1.5 мес
M3 (stores)+2–4 нед
