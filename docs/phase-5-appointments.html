Фаза 5 — Запись на приём

PRD-03 · заявка → подтверждение клиникой · бот + admin + Mini App

Спроектировано Обновлено: 31 мая 2026

Клиент оставляет заявку, клиника подтверждает или отклоняет. Автозапись без участия персонала — не делаем. Детали UX уточняются по анкете для директора (следующая сессия).

Каналы MVP

КтоГдеЧто делает
КлиентTelegram-бот, Mini AppСоздать заявку, «мои заявки»
Админ / регистратураAdmin «Заявки»Очередь, фильтры, подтвердить / отклонить / перенести
ВрачБот (staff mode)Уведомление о новой заявке, быстрые действия

Не в MVP: RuStore/mobile app, полный ЛК клиента, FCM push врачам, автобронирование слотов.

Архитектура

Клиент → POST /api/v1/clinics/{slug}/appointment-requests (initData)
Admin → GET/PATCH /api/v1/admin/appointment-requests
Staff-бот (whitelist TG id) → новые заявки + inline-действия
Смена статуса → bot SendMessage клиенту

Подфазы

5.0 — Вход

  • Ответы директора по анкете
  • Финальный UX-flow (поля, выбор врача, отмена)

5.1 — Backend + API v1 (~1 нед)

  • Таблицы appointment_requests, staff_telegram_users
  • CRUD заявок, статусы: pending → confirmed / rejected / rescheduled / cancelled
  • Tenant-scoping, rate limit на создание

5.2 — Клиент: бот (~1 нед)

  • FSM «Записаться», команда «Мои заявки»
  • Уведомление «заявка принята»

5.3 — Клиент: Mini App (~3–5 дней)

  • CTA на главной, форма, список заявок

5.4 — Staff: admin (~1 нед)

  • Раздел /appointments, фильтры, действия
  • Настройка staff Telegram IDs

5.5 — Staff: бот (~3–5 дней)

  • Отдельное меню для whitelist, push о новых заявках
  • Inline: принять / отказать / перенести

5.6 — Polish + деплой

  • Тесты, документация API, инструкция для клиники

Оценка

~3–4 недели (1 разработчик) после утверждения UX по анкете.

Связи

  • PRD-05 (баннер): не блокирует Фазу 5
  • telegram_users (M0): уже в prod
