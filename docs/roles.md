# Ролевая модель

## Роли

| Роль | Описание |
|---|---|
| `admin` | Полный доступ ко всему |
| `editor` | Создание и редактирование черновиков |
| `groomer` | Только раздел груминга |

JWT токен содержит: `user_id`, `clinic_id`, `role`, `exp` (24h).

## Матрица прав

| Действие | editor | admin | groomer |
|---|---|---|---|
| Просматривать всё | ✅ | ✅ | ❌ (только /grooming) |
| Создавать/редактировать черновики (статьи, врачи) | ✅ | ✅ | ❌ |
| Публиковать статьи и врачей | ❌ | ✅ | ❌ |
| Редактировать опубликованные | ❌ | ✅ | ❌ |
| Удалять контент | ✅ | ✅ | ❌ |
| Управлять пользователями | ❌ | ✅ | ❌ |
| Менять настройки клиники | ❌ | ✅ | ❌ |
| Груминг (породы, шаблон, записи) | ✅ | ✅ | ✅ |

## Поведение в UI (admin)

- `groomer` — все роуты кроме `/grooming` редиректят на `/grooming`
- `editor` — кнопки публикации и редактирования опубликованного скрыты
- `admin` — полный доступ, раздел "Пользователи" в навигации

```tsx
const { user } = useAuth();
const isAdmin = user?.role === 'admin';

// Скрыть публикацию для editor
{isAdmin && <Button onClick={publish}>Опубликовать</Button>}
```

## Создание первого пользователя

При первом запуске бэкенда (пустая таблица `users`) автоматически создаётся
пользователь `admin` из env-переменных `ADMIN_LOGIN` / `ADMIN_PASSWORD`.

Последующих пользователей создаёт admin через панель управления.

## Проверка прав на бэкенде

Роль проверяется в JWT middleware (`internal/middleware/auth.go`).
Фронтенд скрывает UI-элементы для UX, но бэкенд всегда является авторитетным источником прав.
